# 山海幻灵 · 商业完成度路线图（v0.003）

> 这份文档回答用户那句「按照成熟的商业游戏的思维和完成度要求去不断完善这个游戏」。
> v0.003 起，路线图按「召唤/培养/融合」内核重排；旧的「武器 / 数值卡」相关条目已作废。

---

## 1. 当前位置

**v0.003 是一个能跑、能被机器验证的 Godot 2D / 全量 C# 垂直切片，不是一个完成品，也不是一个被真人玩过的游戏。**

| 层级 | 判据 | 状态 |
|---|---|---|
| **L0 工程可运行** | 能打开、能进 Play、主循环走通、有可复核验证证据 | ✅ 已达成：`dotnet build` 0 错误、headless 导入 0 解析错误、冒烟 24/24 PASS、静态自检全过 |
| **L1 核心循环成立** | 有明确的资源 → 决策 → 反馈闭环 | ✅ 已达成：灵韵 → 唤灵三分支 → 军团变化 → 自动战斗 → 再掉灵韵 |
| **L2 内容厚度** | 物种 / 配方 / Lore 数量足以支撑多局不同构筑 | ⚠️ 部分：10 物种 / 5 配方 / 6 Lore，可玩但远未到 BM 的 190+ 规模 |
| **L3 物理与表现** | 真实碰撞、动画、特效、音效、中文字体离线可用 | ❌ 未做：飞行体 + 距离判定、纯色块、无音效、字体依赖系统 |
| **L4 平台适配** | 手柄、分辨率自适应、导出包 | ❌ 未做 |
| **L5 长线留存** | 图鉴、职业、赛季、成就、云存档 | ❌ 未做 |
| **L6 工程化 / 合规** | CI、自动化测试、崩溃上报、存档加密、许可证 | ❌ 未做 |

## 2. 优先级队列（按性价比，不按「听起来厉害」）

| 优先级 | 事项 | 完成判据 |
|---|---|---|
| **P0** | **真人按一次 Play** | 中文正常、跳跃落点合理、相机不晕、唤灵面板在 1280×720 下可读、能连续玩 3 夜 |
| **P0** | 回答 `design-freeze.json` 的 **Q2 / Q3** | ★助手提案 7 项保留与否、昼夜是否保留 → 这两条决定后续所有数值与结构 |

| P1 | 把 BMP 同源物种做出可辨识差异（动画 / 色调 / 攻击特效） | 同一物种的野生与契约形态一眼可分 |

| P2 | Seal / Banish / Giga Banish（BM 的随机性驯化层） | 跨局影响候选池，可复现 |

| P2 | 对象池 + 敌人物理碰撞 | 高波次下帧率稳定 |
| P3 | 18 职业 Heritage / Heroic Force 自愿难度旋钮 / 190+ 召唤项 | 内容量级接近商业同类 |
| P3 | 音效音乐、手柄、CI、崩溃上报、存档加密、L6 合规 | 发布前清单 |

## 3. 已作废的旧方向（v0.001~v0.002 口径，不再追）

- 六把武器平衡、武器切换、武器解锁（v0.003 整系统删除）
- 14 张纯数值卡的抽取与重掷（改为三类唤灵分支）
- 「白天炮台自动开火」（与「幻灵师不攻击」冲突，已重定位为营地器具）
- 敌人跨层追击弧线插值 Q16（旧 Unity 侧问题，Godot 侧用飞行体 y 插值，未再列为待办）

---

## 4. 版本节奏

用户明确要求「版本更新不要那么快」：`v0.001 → v0.002 → v0.003`，每次 +0.001；里程碑才跳 `0.010 / 0.100`，商业发布升 `1.000`。每次提交同步四处版本口径（`project.godot`、`design-freeze.json`、`README.md`、`docs/roadmap.md`）并打同名轻量 tag。Unity 侧 `v0.0001~v0.0003` 是另一条版本线，不并入本仓库。

---

## 5. 一句话结论

**先把 Q2 / Q3 定了，再按一次 Play。** 在没被真人玩过之前继续堆系统，只会把「不确定」堆得更高。
