# 山海幻灵 · 商业完成度路线图（v0.002）

> 回答的是「从可运行雏形到商业成品还差什么」。**不断完善 ≠ 一次全做完**：每级有可验收的完成定义，上一级没站稳就堆功能，是独立游戏最常见的死法。
> 本文件接续源 Unity 工程 `docs/roadmap.md` 的 L0–L6 分级，但**按 Godot 工程重新起算**，版本号自 v0.001 开始。

---

## 0. 判断标准

| 维度 | demo / 原型 | 商业成品 |
|---|---|---|
| 目标 | 证明核心循环能跑 | 陌生玩家 30 秒理解、10 分钟一次正反馈、愿意再来一局 |
| 数值 | 能跑就行 | 每条曲线有意图 + 极值验算 + 实测数据 |
| 反馈 | 逻辑正确 | 每个动作有视觉/听觉/手感回应 |
| 美术 | 占位即可 | 统一风格、可读轮廓、图集与规格策略 |
| 架构 | 能改 | 数据与逻辑分离、模块可替换、可测试 |
| 范围 | 加功能 | **砍功能**：把不做的事写清楚 |

## 2. 本轮刻意不动的三块

1. **真人 Play Mode 验证**：headless 只证明「代码不报错、状态机走得通」，**不证明能玩**。连续多轮堆系统而没人真正按过 Play，是当前最大风险。
2. **L4/L6 大补齐**：在没试玩前补音效、UI 皮肤、导出管线，很可能基于错误手感做无用功。
3. **源工程未迁移系统全量搬运**：先确认核心循环在 Godot 里好玩，再决定哪些值得搬。

## 3. 建议的下一批顺序（按性价比，非排期承诺）

| 优先级 | 事项 | 验收标准 |
|---|---|---|
| **P0** | **真人按一次 Play**，记录：能否进主页面、中文是否正常、跳跃能否跨层、相机是否晕、HUD 能否点中 | 一份试玩记录，含至少 1 局完整昼夜 |
| P1 | 修试玩暴露的问题（数值/布局/字体） | 问题逐条关闭，版本号 +0.001 |
| P1 | **C# Phase 2：数据/核心层 7 个脚本转 C#**（见 `docs/csharp-migration.md`） | `dotnet build` 0 错误 + 冒烟 12/12；两套 GameConfig 常量收敛为一套 |
| P1 | 补 `export_presets.cfg` 出一个 PC 可运行包 | 双击能启动、无缺失资源 |
| P2 | C# Phase 3 玩法层 / Phase 4 UI 层 | 每批独立编译 + 冒烟，全部脚本转 C# |
| P2 | 手柄适配（Godot InputMap 摇杆/按钮 + UI 焦点导航） | 纯手柄能走完一局 |
| P2 | 音频：程序化音效或轻量音频文件 | 开火/受击/拾取有反馈 |
| P3 | Boss / 夜晚事件 / 精英词缀 等源工程内容按批迁 | 每批单独提版 + 冒烟 |
| P3 | 敌人与子弹换 `Area2D`，引入对象池 | 100 敌同屏帧率可测 |
| P3 | 存档加密 + 设置/图鉴/教程/键位重绑定 | L5 完成定义达成 |

## 4. 诚实结论

v0.002 **是一个能跑、能被机器验证、且开始按用户要求向 C# 迁移的 Godot 2D 垂直切片，不是一个完成品，也不是一个被真人玩过的游戏**。
迁移前源工程已连续多轮「编译/冒烟通过但真人 Play 为 0」；本轮把这条欠债原样带过来了。
**下一轮最该做的不是加系统，是打开 Godot 按一次 Play。**

---

## 5. 版本口径

自 v0.001 起，每次有意义变更 +0.001；里程碑（首个真人 Play 验收 / 首个正式内容版本）才跳 0.010 或 0.100；商业可发布再升 1.000。每次提交同步 `project.godot` 的 `config/version`、`docs/design-freeze.json` 的 `version`、README 标题，并打同名 git tag。
