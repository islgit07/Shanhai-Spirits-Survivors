# 升级系统 / 单槽存档 — 决策记录（2026-11-16，v0.0005 随从系统第 3 块）

> 用户描述的完整蓝图很大（主角升级 + 魂魄 + 局外养成 + 局内吸血鬼幸存者式领取/合成 + 存档）。
> 用户明确「可以拆开来做」，本记录只拍板**第三块：升级界面基础版**的口径；
> 局内领取/合成、战斗掉落属后续块，不在本 record 范围。

| 决策 | 选择 | Why | Revisit when |
|---|---|---|---|
| 交付范围 | 数据底座 + 能打开的界面（魂魄→加点→存盘闭环） | 用户拍板「数据底座+界面」；先跑通闭环再美化 / 扩树 | 界面需要正式美术时 |
| 魂魄来源 | 存档预置初始 300，不做注入按钮；真实掉落留第五块 | 用户「以后会做的 你先默认一个数」；本块无战斗 | 战斗 / 怪物死亡掉落实装时 |
| 存档格式 | JSON + `user://shanhai_save.json` + version 字段 + 迁移钩子 | save-load 范式：玩家可控数据不用 Resource（加载 .tres 会执行脚本，不安全）；`res://` 导出后只读 | 存档需要加密 / 多槽时 |
| 存档槽位 | 单槽自动存（任何加点/升级立即 `Save()`） | 用户拍板「单槽自动存」 | 需要多周目 / 多角色时 |
| 升级树数据 | 每本命一张 `UpgradeTreeDef.tres`，平行数组存二叉树 | 用户「每一个本命怪的加点都不一样」；加随从 = 丢一张卡零代码；平行数组可在 Inspector 编辑、避免嵌套 sub-resource 手写易错 | 树节点数超过 ~50，需要可视化编辑器时 |
| 加点结构 | 二叉树（根 + 左右子），子节点需父节点 ≥1 级才解锁 | 经典加点树前置语义，能体现「每个本命不同结构」 | 用户给出正式树设计稿时 |
| 初期节点收益 | 全部只加血量（NodeHpBonus），节点名/耗费各树不同 | 用户「现在是开发初期，你都用加血量先设计，以后再修改丰富加点树」 | 用户设计好攻击/敏捷/技能节点时 |
| 货币种类 | 魂魄作唯一货币，主角加点与随从局外养成共用 | 单一资源易平衡；用户魂魄定义就是「金币换名」 | 需要区分局内/局外货币时 |
| 局外养成项 | 初始等级 / 血量 / 攻击 / 敏捷，各存最终值（非加点次数） | 用户点名这四项；存最终值使基值调整不篡改老存档 | 局内属性系统实装、需要继承时 |
| 界面入口 | 开始页「养成」按钮 → UpgradeScreen.tscn，顶部三本命页签 | 用户授权「startpage 你可以碰」；局外养成按随从分，进界面先选本命 | 需要局内热键打开时 |
| 局外/局内边界 | 本块属性只在局外界面生效，不改主角的实际战斗数值 | 项目当前无 HP/攻击概念，硬接会造成假实现；用户「局外生长的系统做局外就行」 | 第五块战斗系统与 HP 实装时 |

## Open / deferred
- **局内随从系统**（第四块）：活一定时间 / 主角升级就领取新随从；相同随从合成更高资质——依赖战斗与计时，未实现。
- **魂魄掉落**（第五块）：怪物死亡掉落魂魄，替换初始 300 的演示口径——依赖战斗，未实现。
- **加点树丰富化**：加攻击 / 敏捷 / 技能节点，由用户自行设计技能后逐块加；本块 AI 未创造任何技能。
- **跟随 AI**：仍未实现（随从实体当前固定摆在主角右上方）。
- **存档多槽 / 迁移**：目前只有 v1，无历史版本需迁；`Migrate()` 钩子预留。
- **测试存档复位**：升级界面冒烟结束会 `ResetToDefault()` 把玩家档复位到 300 魂，避免测试污染。

## 用户原始口径（逐字）
- 「根据魂魄（怪物死亡凋落物 可以理解为金币换了个名字 然后你记得加一个显示魂魄数量的UI 进行加点升级 会有二叉树 每一个本命怪的加点都不一样 现在是开发初期，你都用加血量先设计以下 以后再修改 丰富加点树）」
- 「随从升级 本命随从会有一个局外养成系统，会继承当前存档的（对 你还需要做一个存档系统）局外成长 如，初始等级，血量，攻击力，敏捷等 局外生长的系统做局外就行」
- 「局内系统你要做的是 类似吸血鬼幸存者 活一定时间/主角升级就可以领取一个新的随从 相同随从合成更高资质的随从 那种感觉」
- 拍板回答：第一块=数据底座+界面；魂魄「以后会做的 你先默认一个数」；入口「startpage 你可以碰」；存档「单槽自动存」。
