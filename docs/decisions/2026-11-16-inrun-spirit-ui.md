# 局内随从界面（第四块 UI + 可跑逻辑）— 决策记录

> 2026-11-16，v0.0005。目标沿用 `2026-11-16-upgrade-system.md` 已记录的第四块口径：
> 「活一定时间 / 主角升级领取新随从、相同随从合成更高资质」。本轮只做界面与最小可跑逻辑，
> 不接战斗、不做魂魄掉落、不创造任何技能名或技能效果。

| 决策 | 选择 | Why | Revisit when |
|---|---|---|---|
| 交付范围 | 界面 + 可跑逻辑：能开、能选、能合成；触发用调试按钮模拟 | 用户拍板「界面 + 可跑逻辑」；战斗/掉落尚未实现 | 怪物死亡掉魂魄、真实升级条件实装时 |
| 界面形态 | ESC 双栏：左窄栏放原「继续/设置/退出」，右大栏放随从队伍面板；三选一另弹窗 | 用户「原来的 ESC 占很小一部分，主要界面给大界面」；覆盖早先「按键呼出大面板」的想法，不新占键 | 需要游戏中不暂停查看队伍时 |
| 三选一触发 | 局内「模拟升级」调试按钮 | 用户选；确定性、可重复验证，以后换触发口即可 | 接真升级系统时 |
| 弹窗期间 | 暂停游戏，选完恢复 | 用户选；同吸血鬼幸存者升级选卡 | 需要边跑边选时 |
| 卡片内容 | 纯占位文案「随从 A / 等级 1」等 | 用户选；技能由用户自己设计，AI 不创造 | 用户给出正式随从名 / 技能表时 |
| 领取逻辑 | 选新随从 → 加入队伍；选已在队同名随从 → 合成、资质 +1 | 用户选，符合已记录的第四块目标 | 需要更细的资质/等级公式时 |
| 数据归属 | 当局临时，退出即清，不写存档 | 用户选；不污染局外养成存档 | 需要跨局继承时 |
| 队伍容量 | 4 格（AI 定的默认值，用户未点名） | 够演示领取与合成，不刷屏 | 用户指定容量时 |
| 候选池 | 6 个占位随从 A~F（AI 定的默认值） | 保证三选一有随机空间，且全是占位无技能 | 用户给出真实随从表时 |
| 数据存放 | `GameRoot` 持有一个纯 C# `RunRoster` 实例；零 autoload / 零静态可变状态 | 项目既定架构；当局数据与存档隔离 | 局内实体需要独立拥有状态时 |

## Open / deferred
- 战斗、怪物死亡掉魂魄、真实升级触发条件——第五块及以后。
- 技能名与效果、攻击/敏捷等属性——由用户设计，AI 未创造。
- 局内随从跟随 AI —— 仍未实现（`spirit_pet.tscn` 实体目前固定偏移）。
- 手柄暂停键 / 手柄 UI 导航映射 —— 等统一做手柄支持时再接，`project.godot` 本轮不碰。
- 队伍容量与候选池均为 **assumed** 默认值，用户可一句话改。
