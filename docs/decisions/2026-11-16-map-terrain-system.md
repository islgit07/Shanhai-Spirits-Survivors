# 地图地形类型系统 — 决策记录

用户 2026-11-16 提出：「以后会有其他地图的类型（火山地形、雪山地形等），目前的地图生成可以加一个系统，目前这个就是默认」。按 `godot-grill` 分轮拍板，以下是开发者决策，技术选型由模型据答案推导。

| 决策 | 选择 | 为什么 | 何时重开 |
|---|---|---|---|
| 抽象层次 | 策略：每种地形一套独立生成算法，共用容器/查询接口 | 火山要熔岩池、雪山要冰面，不是只换颜色和权重；用户明确「各有各的造法」 | 若确认所有地形其实只换数值 |
| 当前地图定位 | 默认地形（Default），规则逐字不变搬入 | 用户明确「目前这个就是默认」「默认地形」 | 用户要借机调规则时 |
| 参数 home | Resource `.tres` 配置卡片，Inspector 可调 | 用户明确选「直接做成编辑器配置卡片」，以后自己拖数值不用改代码 | 参数项膨胀到难维护时 |
| 类型选择时机 | 暂固定默认，接口/注入点留好 | 目前只有一种地形；以后由开局逻辑/场景指定 | 加第二种地形或白箱要切换时 |
| 数据落点 | 地形配置做 Resource，生成器做 C# 类，BlockField 退为容器 + 查询门面 | 项目零 autoload / 零 GDScript 基线不变；策略模式不需要全局状态 | — |

## 已由模型决定的事实（非用户决策）

- 语言 C# net8.0、Godot 4.7.2（项目既有基线，不重新问）。
- 策略接口放 `scripts/csharp/gameplay/`，Resource 配置类同目录，`.tres` 实例放 `resources/maps/`。
- 现有 9 条规则（MAP-001~009）作为参数默认值填入 Resource，算法逻辑原样迁入默认生成器，不改一个数值/概率。
- 种子分域沿用 `Rng.DeriveSeed64(seed, "blocks")`，地形类型不额外改变种子语义。

## Open / deferred

- 火山地形、雪山地形的**具体生成算法** —— 本次不做，只留扩展点。
- 白箱内切换地形类型的热键/UI —— deferred（用户选「暂固定默认」）。
- 地形类型由种子派生 —— deferred（与种子分域规划的接口预留，本轮不接）。
